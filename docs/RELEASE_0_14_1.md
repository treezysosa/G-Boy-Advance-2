# 0.14.1 — launch colours, SoundFont drops, library folder and startup recall

Each newly loaded plugin or standalone instance chooses one of the ten skins, excluding the last colour opened. The shared launch history is `appearance.json` beside the user Presets and SoundFonts directories. Appearance history is touched only on first editor creation; plugin scanning, state serialization/restore and audio processing do not touch that file. A process-local guard and a bounded cross-process lock serialize history updates; a broken, unwritable or busy preference never prevents UI creation. Across-process no-repeat history requires writable app data and successful locking.

Close/reopen of the same instance’s editor, presets, window size/visibility and state refresh keep the colour. SELECT → NEW COLOUR ON LOAD is on by default, including older DAW projects. Turn it off, choose a skin and save the project to keep that specific colour. The setting and fixed skin remain per-instance, non-automatable project properties; all 64 audio parameter IDs, program order, 530 presets, SF2 playback and 16-frame latency are retained.

Drop **one .sf2 file anywhere on the plugin window**, including child controls and the ROM Hacks, preset or advanced panels. The hover overlay identifies an accepted drop. Dropping opens ROM Hacks (or keeps the already-open panel), starts the existing bounded asynchronous loader, activates the bank on successful publication and exposes its instruments. LOAD SF2 remains available. Uppercase .SF2 extensions and Unicode/spaces in paths work. Multiple files, relative paths and other extensions are rejected without changing the instrument. Invalid .sf2 contents, missing files and unsupported banks show loader errors and retain the working bank. No new sample decoder, general audio importer or audio-thread file I/O is introduced.

Windows shell drag and drop requires compatible process privilege levels; normally run File Explorer and the DAW without administrator elevation. Host restrictions may prevent external shell drops; LOAD SF2 remains an alternative. Banks retain the existing 128 MiB / PCM-SF2 limitations and project-cache backup requirements in RELEASE_0_13.md. No SoundFont or recorded audio is bundled.

## Default SoundFont folder and startup recall

ROM Hacks provides a browsable folder at `%APPDATA%\Treezy Audio\G Boy Advance 2\SoundFont Library`, an upper bank selector and the existing lower instrument selector, OPEN FOLDER, CHOOSE FOLDER, REFRESH and REMEMBER LAST BANK. LOAD SF2 starts in the chosen directory. The folder can be changed and is remembered for new instances. Scans are nonrecursive and bounded to 512 banks / 4096 visited entries; regular .sf2/.SF2 files are listed, other formats/directories/symlinks ignored.

Successful explicit bank loads and instrument selections remember their immutable cached bank reference and selected instrument. New instances/standalone restarts can recall it without the original file or another file picker. Recall is on by default and can be disabled. DAW project synth/SF2 state wins over startup defaults; state restore does not change the global last bank. Explicit synthesis selection cancels pending recall. Missing cached banks stay silent with an error. All scan, preference persistence and bank file work runs on the loader worker; startup begins only when audio is prepared or the editor opens, avoiding decoding during bare plugin discovery. Startup history is `soundfont-library.json`, distinct from project state and `appearance.json`. Dirty-field merging under process-local/cross-process locks prevents unrelated simultaneous folder/recall changes from replacing each other. Unreadable, corrupt, future-format or busy preferences are reported and retained rather than silently overwritten.

The browse folder contains user originals; the existing SoundFonts cache retains project-safe copies. No originals are renamed/deleted and no bank is bundled. Back up both folders and the preferences. New tests cover default/custom folders, uppercase/Unicode files, UI bank loading, nonrecursive filtering, scan bounds, corrupt/missing folders/preferences, last instrument recall in a separate OS process after removing the original, no duplicate cache on startup, synth/SF2 project precedence, explicit factory cancellation, recall opt-out, unrelated preference updates from separate instances, and scans/publications during audio.
